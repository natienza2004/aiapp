# REST API Documentation

## Base URL
```
http://localhost:3000
```

## Content-Type
All requests and responses use `application/json` content type.

---

## Endpoints Summary

| Method | Endpoint | Description | Status |
|--------|----------|-------------|--------|
| GET | `/items` | Get all items | 200 OK |
| GET | `/items/:id` | Get single item | 200 OK / 404 Not Found |
| POST | `/items` | Create new item | 201 Created / 400 Bad Request |
| PATCH | `/items/:id` | Update item | 200 OK / 400 Bad Request / 404 Not Found |
| DELETE | `/items/:id` | Delete item | 200 OK / 404 Not Found |

---

## GET /items

Retrieve all inventory items from the database.

### Request
```http
GET /items HTTP/1.1
Host: localhost:3000
Content-Type: application/json
```

### Response (200 OK)
```json
[
  {
    "id": 1,
    "name": "Laptop",
    "quantity": 5,
    "category": "Electronics",
    "description": "Dell XPS 13 Laptop",
    "createdAt": "2026-04-06T10:30:00.000Z"
  },
  {
    "id": 2,
    "name": "Mouse",
    "quantity": 50,
    "category": "Accessories",
    "description": "Wireless Mouse",
    "createdAt": "2026-04-06T10:35:00.000Z"
  }
]
```

### Response (Empty List)
```json
[]
```

### Status Codes
- **200 OK**: Items retrieved successfully
- **500 Internal Server Error**: Database connection failed

### Notes
- Returns empty array if no items exist
- Items are returned in order of creation
- All fields are included in response

---

## GET /items/:id

Retrieve a single item by its ID.

### Request
```http
GET /items/1 HTTP/1.1
Host: localhost:3000
Content-Type: application/json
```

### URL Parameters
| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | integer | Item ID (required) |

### Response (200 OK)
```json
{
  "id": 1,
  "name": "Laptop",
  "quantity": 5,
  "category": "Electronics",
  "description": "Dell XPS 13 Laptop",
  "createdAt": "2026-04-06T10:30:00.000Z"
}
```

### Response (404 Not Found)
```json
{
  "statusCode": 404,
  "message": "Item with id 999 not found"
}
```

### Status Codes
- **200 OK**: Item retrieved successfully
- **404 Not Found**: Item with specified ID does not exist
- **500 Internal Server Error**: Database connection failed

### Notes
- ID must be a positive integer
- If item does not exist, returns 404
- All item fields are included in response

## POST /items

Create a new inventory item.

### Request
```http
POST /items HTTP/1.1
Host: localhost:3000
Content-Type: application/json

{
  "name": "Keyboard",
  "quantity": 20,
  "category": "Accessories",
  "description": "Mechanical Keyboard RGB"
}
```

### Request Body

| Field | Type | Required | Validation |
|-------|------|----------|-----------|
| `name` | string | Yes | Non-empty, max 255 characters |
| `quantity` | number | Yes | Non-negative integer |
| `category` | string | Yes | Non-empty, max 255 characters |
| `description` | string | Yes | Non-empty, max 1000 characters |

### Response (201 Created)
```json
{
  "id": 3,
  "name": "Keyboard",
  "quantity": 20,
  "category": "Accessories",
  "description": "Mechanical Keyboard RGB",
  "createdAt": "2026-04-06T11:00:00.000Z"
}
```

### Response (400 Bad Request - Missing Field)
```json
{
  "statusCode": 400,
  "message": "Name is required"
}
```

### Response (400 Bad Request - Invalid Quantity)
```json
{
  "statusCode": 400,
  "message": "Quantity must be a non-negative number"
}
```

### Status Codes
- **201 Created**: Item created successfully
- **400 Bad Request**: Missing or invalid fields
- **500 Internal Server Error**: Database connection failed

### Notes
- All fields are required
- `id` is auto-generated by database
- `createdAt` is auto-set to current timestamp
- Quantity must be >= 0
- Response includes the created item with generated ID and timestamp

## PATCH /items/:id

Update an existing inventory item.

### Request
```http
PATCH /items/1 HTTP/1.1
Host: localhost:3000
Content-Type: application/json

{
  "quantity": 10,
  "description": "Updated description"
}
```

### URL Parameters
| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | integer | Item ID (required) |

### Request Body (Partial Update)

| Field | Type | Required | Validation |
|-------|------|----------|-----------|
| `name` | string | No | Non-empty if provided |
| `quantity` | number | No | Non-negative integer if provided |
| `category` | string | No | Non-empty if provided |
| `description` | string | No | Non-empty if provided |

### Response (200 OK)
```json
{
  "id": 1,
  "name": "Laptop",
  "quantity": 10,
  "category": "Electronics",
  "description": "Updated description",
  "createdAt": "2026-04-06T10:30:00.000Z"
}
```

### Response (404 Not Found)
```json
{
  "statusCode": 404,
  "message": "Item with id 999 not found"
}
```

### Response (400 Bad Request)
```json
{
  "statusCode": 400,
  "message": "Quantity must be a non-negative number"
}
```

### Status Codes
- **200 OK**: Item updated successfully
- **400 Bad Request**: Invalid field values
- **404 Not Found**: Item with specified ID does not exist
- **500 Internal Server Error**: Database connection failed

### Notes
- All fields are optional (partial update)
- At least one field should be provided for meaningful updates
- `id` and `createdAt` cannot be modified
- Response returns the complete updated item
- `updatedAt` is not tracked in this system

## DELETE /items/:id

Delete an existing inventory item.

### Request
```http
DELETE /items/1 HTTP/1.1
Host: localhost:3000
Content-Type: application/json
```

### URL Parameters
| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | integer | Item ID (required) |

### Response (200 OK)
```json
{
  "statusCode": 200,
  "message": "Item with id 1 deleted successfully"
}
```

### Response (404 Not Found)
```json
{
  "statusCode": 404,
  "message": "Item with id 999 not found"
}
```

### Status Codes
- **200 OK**: Item deleted successfully
- **404 Not Found**: Item with specified ID does not exist
- **500 Internal Server Error**: Database connection failed

### Notes
- Deleted items are permanently removed from database
- No undo or soft delete functionality
- Subsequent requests for deleted item return 404
- Response includes confirmation message

## Data Model

### Item Object

```typescript
interface Item {
  id: number;                    // Auto-increment primary key
  name: string;                  // Item name (required)
  quantity: number;              // Stock quantity (required, >= 0)
  category: string;              // Item category (required)
  description: string;           // Item description (required)
  createdAt: ISO8601Timestamp;   // Creation timestamp (auto-set)
}
```

### Create Item Request

```typescript
interface CreateItemDTO {
  name: string;          // Item name (required)
  quantity: number;      // Stock quantity (required, >= 0)
  category: string;      // Item category (required)
  description: string;   // Item description (required)
}
```

### Update Item Request

```typescript
interface UpdateItemDTO {
  name?: string;         // Item name (optional)
  quantity?: number;     // Stock quantity (optional, >= 0)
  category?: string;     // Item category (optional)
  description?: string;  // Item description (optional)
}
```

## Frontend Integration Notes

### Base URL Configuration
Frontend should use `http://localhost:3000` as the base URL for all API calls.

### Fetch API Usage
```typescript
// Example: Get all items
const response = await fetch('http://localhost:3000/items');
const items = await response.json();

// Example: Create new item
const response = await fetch('http://localhost:3000/items', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ name, quantity, category, description })
});
const newItem = await response.json();
```

### Error Handling
Always check response status before processing:
```typescript
if (!response.ok) {
  const error = await response.json();
  console.error('Error:', error.message);
  // Display error to user
}
```

### CORS Configuration
Backend has CORS enabled, allowing requests from `http://localhost:3000` without special headers.

### Timeout Consideration
Implement reasonable timeouts for fetch requests (e.g., 5 seconds) to handle potential connection issues.

## API Constraints and Assumptions

1. **No pagination**: All items returned in single response
2. **No filtering**: Cannot filter by category or other fields
3. **No sorting**: Items returned in creation order
4. **No search**: Cannot search by name or description
5. **No authentication**: All endpoints publicly accessible (local only)
6. **No rate limiting**: No API rate limits enforced
7. **No versioning**: Single API version (v1 implied in `/` endpoints)
8. **Synchronous operations**: No async processing or background jobs
